♥Open work

Chip farming in Quick Match

How it works today:

  • Every Google account gets 1,000 chips at sign-up and 100 more each day.
  • Only Quick Match moves chips. Private rooms don't.
  • Quick Match seats whoever queues first at the same stake and table size. At a quiet hour, a 2-player queue pairs you with your own second account.
  • The second account loses on purpose. Ten spare accounts can move over 10,000 chips a day to one player, who then tops the leaderboard.
  • The terms say chips have no money value. The harm is a fake leaderboard.
FixWhat it stopsCostDownside
A. Never seat two players from one IP at a Quick Match tableOne person farming from one connectionSmall change in server/rooms.jsRoommates on one wifi can't share a Quick Match table. Private rooms still work.
B. Accounts under 3 days old play stake 10 onlyFresh spare accountsSmall change in find-matchNew players wait 3 days for big stakes.
C. Cap net chips between the same two accounts at 500 a dayFarming through a VPN tooOne extra query per handMore code on the hot path.

Recommended: A and B now. Add C only if the leaderboard still looks wrong.

More instant wins

Today a player wins straight from the deal with four 2s or a dragon (one of every rank from 3 to A). The proposal adds six pairs and five pairs in a row. Odds come from 2,000,000 simulated deals, for one player in one hand:

HandOddsStatus
Four 2s1 in 374In the game
Dragon, 3 to A1 in 1,833In the game
Six pairs, a four of a kind counts as two1 in 219Proposed
Six pairs, a four of a kind doesn't count1 in 244Alternative
Five pairs in a row, no 2s1 in 1,577Proposed

At a 4-player table someone wins instantly about once in 78 hands today. With both new hands it becomes about once in 31, mostly from six pairs.

Files to change:

  • server/game/validator.js: checkInstantWin, plus tests in engine.test.js
  • client/src/components/Game.jsx: names for the new instant wins
  • client/src/pages/Rules.jsx and client/src/i18n/vi/: rules text in both languages

The score tracker needs no change. It records an instant win by player, not by hand type.

Decisions waiting

  1. Ship chip farming fixes A and B?Recommended: yes.
  2. For six pairs, does a four of a kind count as two pairs, and does a pair of 2s count?Recommended: yes to both. It is the common house rule.
  3. Should the new instant wins apply on every hand, with the same +3 bonus as the existing ones?Recommended: yes, every hand, same bonus.

♠Tests

54 automated tests live in server/. Node's built-in test runner finds every *.test.js file. Run them with cd server && npm test. They take about 28 seconds.

Last run: 8 October 2026 on Node 24.13.0. 54 pass, 0 fail.

Unit tests: 27

These call one module's functions directly, with no network and no database. They cover the rules engine, the bots, rooms, names and emotes.

Integration tests: 27

These start a real server on a free port and talk to it the way a browser would. The game server tests use socket.io-client over WebSocket. The SEO tests send HTTP requests with fetch.

What the tests fake

  • The database is never used. Hand saves do nothing, every balance is a fixed number, and emotes use an in-memory table.
  • Google sign-in is replaced by a test header, x-test-user.
  • Turn timers and bot delays shrink from seconds to 5 to 300 ms, so a whole hand plays out in under a second.
